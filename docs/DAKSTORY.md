# DakStory

DakStory — бережный контур непрерывного улучшения приложения. Он собирает проверяемые сигналы качества и превращает их в понятный список следующих шагов, не подменяя инженерное решение автоматическим переписыванием исходников.

## Восемь направлений качества

1. **Security & Privacy** — защита данных, границы доверия и минимальные права автоматизации.
2. **Reliability** — синтаксическая целостность, тесты, сборка и регрессионная устойчивость.
3. **Supply Chain** — зависимости, фиксация версий GitHub Actions и прозрачность сборки.
4. **Accessibility** — доступность управления, фокуса, контраста и экранных дикторов.
5. **Performance** — измеряемые время выполнения, память и нагрузка.
6. **Compatibility** — подтверждённая работа на заявленных ОС, архитектурах и версиях runtime.
7. **Maintainability** — небольшие функции, говорящие имена, прямой поток, guard clauses и отсутствие лишних абстракций.
8. **Product Quality** — понятная документация, предсказуемые сценарии, воспроизводимость и аккуратные ошибки.

## Автоматические проверки

DakStory обнаруживает технологические стеки и тестовые файлы, разбирает Python AST и JSON, проверяет наличие README, SECURITY.md, лицензии и CI, просматривает GitHub Actions на незакреплённые SHA и чрезмерные права, отмечает слишком большие исходные файлы как повод для ревью и формирует JSON/Markdown отчёты.

Доступность интерфейса, производительность аудиорендерера и совместимость сборки с целевыми окружениями получают отдельные пометки для профильной проверки: статический анализ не может подтвердить отсутствие аудиоартефактов, реальные задержки, поведение аудиовыхода или корректность сборки.

## Границы автоматизации

DakStory не запускает команды проекта, не устанавливает и не обновляет зависимости, не обращается к сети, не читает содержимое потенциальных секретов и не изменяет прикладные исходники. Команда safe-fix создаёт корневой .editorconfig только при его отсутствии; существующая конфигурация не перезаписывается. Отчёты хранятся в .dakstory/reports и исключаются из Git.

## Использование

```bash
python scripts/dakstory.py self-test
python scripts/dakstory.py audit
python scripts/dakstory.py audit --json .dakstory/reports/latest.json --markdown .dakstory/reports/latest.md
python scripts/dakstory.py safe-fix
```

CI запускает self-test и статический аудит при push в main, pull request, вручную и по недельному расписанию. Отчёт попадает в GitHub Actions job summary. Синтаксические ошибки Python/JSON делают проверку неуспешной; рекомендации и ручные проверки видны, но сами по себе сборку не блокируют.

## Нормативные ориентиры

- **OWASP ASVS 5.0.0** — ориентир безопасности веб-приложений и сервисов там, где он применим.
- **WCAG 2.2 / ISO/IEC 40500:2025** — ориентир доступности пользовательских интерфейсов; нативные приложения дополнительно проверяются по правилам своей платформы.
- **NIST SP 800-218 v1.1** — опубликованная редакция Secure Software Development Framework. SP 800-218 Rev. 1 v1.2 отслеживается как проект редакции, а не как утверждённый стандарт.
- **GitHub Actions security guidance** — минимальные token permissions, закрепление сторонних actions полными commit SHA и отказ от ненужных секретов.

Стандарты применяются по области действия. Статический отчёт DakStory не является аудитом, сертификатом соответствия или обещанием отсутствия уязвимостей.

## Человечный стиль кода

DakStory поддерживает естественный авторский код: осмысленные имена, небольшие функции с одной задачей, раннюю проверку входных данных, понятные сообщения об ошибках и комментарии, объясняющие решение. Читаемость не должна становиться поводом для лишних абстракций или нарушения обратной совместимости.
