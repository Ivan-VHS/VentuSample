# Architecture and audio contract

**Baseline:** C++20 scalar offline renderer · Qt 6 Widgets · PCM16 WAV · manifest v2.

| Layer | Responsibility |
|---|---|
| Qt desktop | controls, folders, results/log, preferences |
| Parameters | typed settings, validation, seed, limits |
| Renderer | pattern scheduler, synthesis, scheduled event frames, stereo float buffers |
| Stochastic Router | weighted DSP pool, deterministic topology and trigger planning, offline segment processing |
| Asset I/O | PCM16 import, 4-slice chop, pitch resample, WAV export |
| Master | sampler color, linked stereo compression, sample-peak ceiling |
| Manifest | generator settings, stochastic plan metadata, key/mode, peak/RMS/crest |
| Plugin host | 19 versioned built-in plugins, enable/disable lifecycle, bounded handlers and public registration API |
| Tests | validation, repeatability, variations, WAV round-trip, stochastic DSP, schemas and plugin lifecycle |

## Stochastic routing

The offline router mutates a rendered stereo buffer before WAV encoding. It draws weighted effect entries from the configured pool without replacement and creates serial, parallel or hybrid routes. Its eight built-in processors are low-pass, high-pass, saturator, bitcrusher, delay, reverb, ring modulation and stereo width.

| Control | Contract |
|---|---|
| Pool | 8 individually switchable effects; default weights are defined in `defaultStochasticPool()` |
| Topology | Hybrid, serial or parallel; 2–4 bounded branches |
| Triggers | Per file, per bar, or renderer-scheduled onset/event frames |
| Intensity | 0–100%; zero-intensity path is transparent |
| Wet / feedback | maximum 65% / 72% |
| Crossfade | 5–20 ms at mutation boundaries |
| RMS gain | bounded compensation, 0.5–2× |
| Peak guard | sample peak ceiling no higher than −0.3 dBFS |
| Seed | generator seed + variation + trigger index |

Onset mode uses event frames generated by the procedural renderer. It does not perform transient detection on arbitrary imported WAV material. Triggered routes are offline, not real-time plugin hot-swaps.

## Numeric limits

| Parameter | Range |
|---|---|
| BPM / bars / variations | 60–190 / 1–16 / 1–32 |
| Swing | 50–68% |
| Density / grit / saturation / stereo | 0–100% |
| High-pass / low-pass | 20–300 Hz / 2–20 kHz |
| Snare offset | −30…+30 ms |
| Bus compressor | 1:1–12:1 |
| Sample rate | 22050 / 44100 / 48000 / 96000 Hz |
| Source WAV | PCM16 mono/stereo, 8–192 kHz |
| Source bounds | 128 MiB / 20,000,000 frames |
| Pitch / mix | −12…+12 semitones / 0–100% |

Low-pass must exceed high-pass and stay below 0.49× sample rate. Source transposition uses resampling, not time-stretch.

## Manifest and tonality

Manifest v2 records stochastic enablement, seed, intensity, trigger, pool mask and topology; each file entry stores the route names actually selected for that output. These are optional schema fields so existing v2 manifests remain valid. v1 remains supported.

| Asset | Key metadata |
|---|---|
| Full Loop / Melody / Bass | selected root + scale |
| Drums | none |
| One-Shot Kit | pitched bass/pluck only |

Key labels describe generation settings, not auto-analysis of imported audio. Existing output files are not overwritten. Golden Era profile: fixed source-slice order 0–2–1–3; kick/snare-weighted voicing and restrained hats. User BPM, swing and snare offset remain authoritative.

Rendering is offline on a worker thread. No real-time callback or audio-device access is provided.
