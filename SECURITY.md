# Антивирус «Веельзевул» — SECURITY.md

Версия политики: **1.0.0** · **66 правил** · 4 уровня по 15 правил + 6 общих.

«Веельзевул» — многоуровневый контур защиты репозитория. Канонический машинный источник правил: [`security/beelzebul.v1.json`](security/beelzebul.v1.json). Проверка выполняется локально и в GitHub Actions без исполнения сканируемого кода.

## Вердикты и приоритет

| Статус | Значение | Поведение CI |
|---|---|---|
| `blocked` | Критическая блокирующая находка | CI завершается ошибкой |
| `review` | Предупреждение или неоднозначный риск | Требуется анализ; не считается доказанной атакой |
| `clear` | Блокирующих находок нет | Сканирование завершено |

Сканер read-only: не исправляет файлы, не перемещает их в карантин и не запускает проверяемый проект. Значения секретов не выводятся в отчёты.

## Уровни защиты

1. **Атомарный** — байты, строки, токены, кодировки и метаданные путей.
2. **Атомный** — функции, модули, зависимости, границы доверия и локальные связи.
3. **Ядерный** — Git, защищённые ветки, права, workflow и выпуск артефактов.
4. **Квантовый** — межветочные корреляции, каскадные зависимости, риск и согласованность политик.
5. **Общий контур** — единство правил, вердикты, исключения и адаптация.

## Граница автоматизации

Автоматический анализ обнаруживает структурные и текстовые признаки угроз, но не доказывает отсутствие уязвимостей. Настройки защиты веток, авторство коммитов, права GitHub, подписи тегов, история audit log и параллельные PR требуют проверки средствами GitHub и review владельцев. Эти пункты не симулируются локальным сканером.

Квантовый уровень — инженерное название для корреляционного анализа; он не заявляет физическое квантовое вычисление и не выводит намерения автора из времени коммитов.

## Запуск локально

```sh
python tools/beelzebul.py
python tools/beelzebul.py --json --output beelzebul-report.json
python tools/beelzebul.py --base-ref origin/main
python -m unittest discover -s tests -p 'test_beelzebul.py' -v
```

## Исключения

Исключения задаются только в `security/beelzebul.v1.json`, на конкретное правило и путь. Обязательны причина, ответственный и срок `expires_at` в UTC ISO-8601. Просроченные, wildcard и неограниченные исключения не допускаются. Критические правила baseline нельзя отключать исключением.

## Отчётность и устранение

Каждая находка указывает ID правила, класс, серьёзность, путь, строку, причину и remediation. Секретные значения не включаются. Для локального воспроизведения используйте ту же версию политики и тот же commit. Для высокой неопределённости используйте статус `review` и дополнительное подтверждение; автоматический карантин/удаление файлов не выполняется.
