# CLife — контрольная точка, перешив и вторая жизнь

CLife — переносимый механизм восстановления репозитория. Он работает поверх Git, не заменяет Git-историю, CI, резервное копирование или review и не запускает восстановленный код.

## Три операции

1. **Точка сохранения (savepoint).** Явно перечисленные файлы сохраняются в .clife/state/savepoints/. Каждый объект адресуется SHA-256; манифест фиксирует путь, размер и режим файла. В снимок не попадает содержимое Git-истории или неуказанные файлы.
2. **Перешив (rethread).** plan сравнивает рабочие файлы с проверенным снимком без записи. rethread по умолчанию только показывает план. Флаг --apply обязателен для изменений; перед заменой текущие существующие версии автоматически попадают в аварийную точку сохранения.
3. **Вторая жизнь (revive).** revive возвращает один выбранный путь из сохранённой точки. Он не импортирует, не запускает и не регистрирует старый код автоматически.

## Использование

~~~bash
python .clife/engine.py savepoint --path src/module.c --path README.md --label before-refactor
python .clife/engine.py list
python .clife/engine.py verify sp-<id>
python .clife/engine.py plan sp-<id>
python .clife/engine.py rethread sp-<id>             # только предварительный план
python .clife/engine.py rethread sp-<id> --apply    # явное восстановление
python .clife/engine.py revive sp-<id> --path src/legacy.c
python .clife/engine.py revive sp-<id> --path src/legacy.c --apply
~~~

Пути всегда задаются относительно корня репозитория. Начинайте с небольшого списка важных файлов и храните дополнительные резервные копии отдельно от рабочей машины.

## Инварианты безопасности

- Нет неявного обхода всего репозитория: захватываются только переданные --path.
- Запрещены абсолютные пути, .., .git, symlink-компоненты и включение собственного каталога состояния CLife.
- Лимиты: 64 MiB на файл и 512 MiB на точку сохранения.
- Все снимки проверяются по SHA-256 перед использованием.
- Применение требует --apply; перед перезаписью существующих файлов создаётся аварийная точка.
- CLife не удаляет существующие файлы при штатном восстановлении и не исполняет «оживлённый» код; при откате неудачной транзакции может удалить только точный новый файл, созданный этой же транзакцией.
- Состояние в .clife/state/ локальное и исключено из Git; переносите важные снимки во внешнее защищённое хранилище.

CLife — механизм контролируемого восстановления, а не обещание автоматического исправления логики, безопасности или совместимости. После восстановления обязательны проектные тесты и code review.
